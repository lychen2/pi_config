总体评估

项目概况：这是一个由 14 个独立 Pi 扩展包和少量顶层扩展组成的 TypeScript/JavaScript 配置仓库，包含默认工具栈、Large profile 事务切换、TUI 呈现、模型目录、后台任务与安装脚本。

主要风险：多文件冲突解决没有回滚；Large profile 命令没有命令级互斥；已完成后台任务和日志没有会话内上限。它们分别会造成半完成写入、并发 profile 交换和长期会话资源增长。

已验证亮点：主行为测试和 TypeScript 检查在可执行包中通过；冲突工具会写前重验；Large 模式已有 staging、marker 与恢复流程；配置选择使用临时文件加 rename 保存。

总评：当前可用性较好，但发布可重复性和跨 profile 一致性尚未形成可靠门禁。应先修复事务原子性与并发控制，再建设仓库级验证。

详细发现

F-01 多文件冲突解决可能留下部分写入

High Confirmed

类别：数据完整性 / 工具事务

受影响区域：pi-maestro-tools/src/conflict.ts:136-171

问题：resolveConflicts 预处理完所有目标后逐文件 writeFile，已写列表只用于诊断；第二个文件失败、取消或变更时，第一个文件不会恢复。

for (const file of prepared) { ... await writeFile(file.absolutePath, text, "utf8"); written.push(file.relativePath); }

现实失败场景：conflict://* 在第二个文件写入失败后返回错误，工作树已经是部分解决状态。

最小修复：写入前保存每个原文；失败或 abort 时逆序恢复所有已写文件。

回归测试：构造两个冲突文件，让第二次写入失败，断言第一个文件回到原始字节内容。预计：0.5-1 天。

F-02 Large 切换缺少命令级互斥

Medium Confirmed

类别：稳定性 / 事务

受影响区域：pi-large-mode/index.ts:844-923, 988-1019

问题：命令处理器直接启动异步 activate/deactivate，没有 in-flight promise、mutex 或版本 compare-and-swap。

影响：两个 on/off 请求可读取同一状态并交叉执行目录交换、配置写入和 reload。

最小修复：建立单一切换锁；切换中拒绝新请求，并将锁释放写入 finally。回归：并发 on/on、on/off 时只允许一个事务进入交换阶段。预计：0.5 天。

F-03 bash_bg 不回收已完成任务与日志

Medium Confirmed

受影响区域：pi-maestro-tools/src/bash-bg.ts:114-170, 239-240

问题：MAX_ACTIVE_JOBS 只限制未完成任务；完成后 Job 仍保留在 Map，日志仍位于临时目录，直到 session shutdown。

影响：长会话大量短命令会累计内存、尾部输出和最多 16 MiB/任务的日志文件。

最小修复：完成任务按 TTL 与最大历史数删除 Map 项和日志。回归：超出阈值后断言旧日志及任务记录被清理，活跃限制仍生效。预计：0.5 天。

F-04 模型发现初始化没有本地超时

Medium Confirmed

受影响区域：pi-manager-models/index.ts:125-149, 151-160

问题：没有静态 models 时，初始化调用 discoverModels(initial, apiKey)，未传 AbortSignal；fetch 可无限等待连接半开或不可达端点。

最小修复：初始化使用 AbortSignal.timeout，错误中包含 provider 与 endpoint。回归：mock 永不响应 fetch 并断言固定时间内失败；显式模型配置不得访问网络。预计：1-2 小时。

F-05 缺少仓库级 CI 与统一发布门禁

Medium Confirmed

受影响区域：14 个独立 package manifest、安装器、Large bundle

问题：可见目录中没有 CI workflow 或根级统一入口；每个包独立执行测试、类型检查和打包，容易遗漏关联包或 vendor。

最小修复：加入矩阵脚本，逐包执行 clean install、test、typecheck、pack dry-run，并加默认/Large 安装集合检查。预计：0.5-1 天。

F-06 Pi 核心 peer dependency 以通配符声明

Medium Confirmed

受影响区域：各包 peerDependencies

问题：@earendil-works/pi-coding-agent: "*" 不表达可验证的宿主兼容范围，未来主版本也会被接受。

最小修复：按实际测试收窄为最低至最高支持范围，并在 CI 覆盖最低和当前版本。预计：0.5-1 天。

F-07 Large vendor 快照已与维护源码发生漂移

Medium Confirmed

受影响区域：matugen-chrome.ts、pi-tool-rails/result-bridge.ts 与 pi-large-beautify/vendor/

证据：维护源码包含 agent pulse 与 call renderer 补丁，vendor 对应快照缺少这些分支；Large 实际加载 vendor。

最小修复：同步脚本提供 --check，CI 对映射清单执行无差异校验。回归：比较所有源/vendor 映射并加载 Large 入口。预计：0.5-1 天。

F-08 两个用户可见扩展没有行为测试

Medium Confirmed

受影响区域：pi-brand-header、pi-slim-skills

证据：两个 package manifest 只有 typecheck，没有 test 脚本或对应测试文件。

最小修复：为注册、非 TUI 短路、session reload 和命令切换建立 mock Pi 行为测试。预计：1-2 天。

F-09 Large bundle 关闭 noImplicitAny

Medium Confirmed

受影响区域：pi-large-beautify/tsconfig.json:8

问题：strict: true 被显式 noImplicitAny: false 抵消部分保护，vendor 边界变化可绕过编译期检查。

最小修复：恢复 noImplicitAny 并为现存隐式 any 写出准确类型；将 vendor typecheck 纳入 CI。预计：0.5-2 天。

F-10 关键事务与渲染模块职责过度集中

Medium Confirmed

受影响区域：pi-large-mode/index.ts、pi-tool-rails/result-bridge.ts、pi-gsd/src/index.ts 等超过约 1000 行的模块。

问题：命令编排、外部进程、状态、渲染、补丁和持久化在同一模块；局部改动会跨越过大隐式上下文。

最小修复：优先拆出事务执行器、profile 校验、渲染解析与 patch registry，保持公共导出不变。预计：2-4 天，分阶段实施。

F-11 Todo UI 控制状态为进程级单例

Medium Confirmed

受影响区域：pi-maestro-todo/index.ts:60-65, 250-276

问题：任务数据按 session 存储，但 activeSessionId、widget、展开状态和 UI context 为单例，多会话/树切换可能显示或刷新错误会话。

最小修复：绑定 UI controller 到当前 ExtensionContext，并在 session 切换时显式重置。回归：两 session 切换后断言 context 与 widget 都来自当前 session。预计：0.5-1 天。

F-12 ReadSeek 兼容层存在隐式全局跨扩展契约

Low Confirmed

受影响区域：pi-readseek-compat/index.ts:14-34

问题：通过 Symbol.for("pi-readseek.hashlineState.v1") 和 globalThis 共享状态，字段布局与版本没有显式兼容检查。

最小修复：集中适配接口与版本校验，覆盖首次/并发/字段缺失初始化。预计：0.5-1 天。

F-13 子进程超时路径未等待实际退出

Low 运行时待验证

受影响区域：pi-large-mode/index.ts:230-269

问题：超时后调用 SIGTERM 和延迟 SIGKILL，但立即 reject；后续 staging 清理或交换可能与仍存活的子/孙进程交叉。

修复：超时后等待 close/exit，按进程组终止；用忽略 SIGTERM 的测试进程验证。预计：0.5-1 天。

F-14 Node 版本与测试 TypeScript 执行契约未统一声明

Low Confirmed

证据：多个包使用 node --experimental-strip-types 或直接导入 .ts，package manifest 未统一声明 engines.node/packageManager。

修复：声明最低 Node 版本，统一脚本，并在最低支持版本和当前 LTS clean install 验证。预计：0.5 天。

F-15 开发依赖 Pi 基线不一致

Low Confirmed

证据：不同包混用 0.82、0.84 与旧 pi-ai 开发依赖。

修复：建立默认/Large 组合的支持矩阵，统一或显式分离开发基线。预计：0.5-1 天。

F-16 工具 schema 适配器使用 any

Low Confirmed

受影响区域：pi-tool-rails/index.ts:78-89

修复：以 JsonSchema 或受限 Record 类型表达 reasoning 字段，加入 required 合并/剥离快照测试。预计：0.5 天。

F-17 pi-markdown-preview-compat 供应链审计无法完成

Low Confirmed

证据：本地 npm audit 因 lockfile 与安装树不匹配返回 ENOLOCK；不能据此宣称该包无漏洞。

修复：从干净 lockfile 执行 npm ci 与 audit，将 audit 结果纳入门禁。预计：1-2 小时。

F-18 vendor 同步流程依赖人工执行

Low Confirmed

证据：README 要求修改维护源码后手动运行同步脚本，而 smoke test 不比较源与 vendor。

修复：生成映射清单并让发布前检查在 diff 存在时失败。预计：0.5 天。

F-19 外部模型目录刷新错误缺少端点级观测

Low Confirmed

受影响区域：pi-manager-models/index.ts

问题：发现失败只经扩展初始化错误传播，没有失败次数、耗时和 endpoint 分类记录；间歇性 provider 故障难以与本地配置问题区分。

修复：保留脱敏 endpoint、阶段和超时原因的结构化诊断。预计：1-2 小时。

F-20 审计基线包含大量未提交变更

Info 范围说明

影响：本报告按当前工作树评估，不能将单条发现归因到某一个提交，也不能替代合并后的 clean-tree 复验。

建议：在发布候选的干净工作树上复跑全包测试、vendor check 与审计。
