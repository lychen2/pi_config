# Curated skill deployment

`install.mjs` uses `scripts/deploy-skills.mjs` as the single deployment implementation. Its `installedSkills` list defines the managed release skills, including `manimgx`. Repository `skills/` is distribution source, not a project runtime skill root. Runtime copies are installed globally under the selected agent directory.

Known legacy directories are moved outside skill discovery to `skill-archives/<timestamp>/`. Managed copies in shared roots are also archived before installing the canonical global copy. Unlisted user skills remain untouched. Archived directories retain their original contents; symbolic links are copied with their contents before removal to keep backups readable. Restore the archived directories to their original roots to roll back. An incomplete release fails validation before migration. Deployment copies complete directories rather than merging stale files.

Default lazy loading uses `config/slim-skills-whitelist.json`: empty whitelist and inject arrays. With search available, only the bounded discovery router is injected; search returns metadata and explicit load retrieves instructions. Without search, descriptions and paths remain available as a fallback. This policy does not require injecting any skill body.

`manimgx` replaces `manim-composer`, `manimce-best-practices`, and `manimgl-best-practices` in both global roots. It retains scene planning and adds the ManimGX inspect/render workflow. Existing CE or GL projects retain their engine unless migration is requested. The skill uses Python 3.13 or 3.14; its runtime is installed on demand, outside the Pi installer. After deployment, run `/reload` and use `/skill:manimgx` to load it. The previous skill directories remain in the archive.

UI work uses three managed entries: `design-ui`, `ui-ux-pro-max`, and `huashu-motion`. Start with `/skill:design-ui <task>` after `/reload`. The entry reads the project design system before implementation, then reads one reference for the task: visual direction, a craft specification, or motion and feedback. Interface animation audits run inside `design-ui`. `frontend-design` and `emil-design-eng` are folded into its references and retired from deployment; `review-animations` was already retired. `huashu-motion` keeps its local CLI and assets for films and explainer videos. Previous copies remain archived. See [UI design workflow](ui-design-skills.md) for commands, local search, browser acceptance, sources, and recovery.

Desktop work on the niri host uses `niri-agent`, with Zen Browser and Zed Preview. It runs through `niri msg agent` using the existing bash and read tools. The host AGENTS.md routes interactive browser and GUI requests to this skill. Agent windows open on the `agent` workspace. The old Zen MCP is disabled in the host MCP configuration. Zed uses a separate data directory with links to the user's settings, keymap, and custom themes; avoid editing those shared settings during automation. Zen keeps the dedicated `~/.config/zen-mcp` profile, whose logins are separate from personal profiles. Run `/reload` in an existing Pi session to discover the new skill; start a fresh session to refresh MCP configuration and injected host instructions.

Research uses two entries: `research` for literature, experimental design, analysis, optics, writing and submission preparation; `scientific-visualization` for data plots and editable schematics. Ten former research entries are retired from deployment and archived on the host. Their useful methods are demand-loaded references inside `research`, not nested skill entries. The research workflow adapts ARIS to Pi: use existing project records, retain review and revision rounds, and keep their working traces out of manuscript prose. HERO guides scope and delivery without removing the selected research workflow's quality checks. Data plotting retains its existing scripts, palettes and export settings. See [Research workflow](research-skills.md).

Language editing uses `humanizer-zh` for Chinese and English. Its entrypoint routes to shared editing principles, Chinese diagnostics, English wording and an optional tool-free Gemini call. The standalone `humanizer` entry is retired; its useful English rules are a reference in `humanizer-zh`. Whole-draft cleanup normally returns a diagnosis before rewriting; an explicit direct-edit request completes both in the same turn. The bundled Python helpers produce prose-only candidates and Markdown comparisons, not authorship scores. Install the complete directory into each active host root, including references, scripts and license notices. The Lieflat-derived material is CC BY-NC 4.0, separate from the retained MIT material. See [writing usage](../skills/humanizer-zh/README.md) and [source terms](../skills/humanizer-zh/SOURCES.md).

For measured model-behavior or token comparisons, use the [Pi skill-diet evaluation workflow](../tests/skill-diet/README.md). A deployment check establishes loading and resource availability; it does not establish improved research outcomes. Keep case-specific methods reachable through explicit reference routes.

Verification: `node --test scripts/deploy-skills.test.mjs` exercises migration, repeated installation, dry run, archival and preservation of a custom domain skill. `npm test --prefix extensions/pi-slim-skills` checks discovery-only and fallback behavior.

The September 13 host deployment found 20 skills across the two global discovery roots, no duplicate names, and 3,725 description characters (approximately 932 tokens at four characters per token). Seventeen are managed distribution skills; three existing user utilities remain. These counts exclude additional package-provided skills and are not a tokenizer measurement.
