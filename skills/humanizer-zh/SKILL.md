# Humanizer-zh

中文和英文语言编辑共用这一入口。先读
[共享编辑原则](references/editing-principles.md)，再按任务只读需要的参考。
事实查证、学术论证和图形制作仍由对应技能负责。

## 按需加载

| 任务 | 读取内容 |
| --- | --- |
| 短文直接润色、图注、讲稿和交互标签 | 共享编辑原则即可 |
| 非虚构长文新写或大幅扩写 | 共享原则中的材料充分性判断，配合任务对应的写作技能 |
| 中文整篇去套话、AI 味检查、文件诊断或修改依据 | [中文诊断](references/chinese-diagnostics.md)及[语义判据](references/semantic-criteria.md) |
| 英文润色 | [英文专用规则](references/english-editing.md) |
| 完整草稿需要额外的 Gemini 润色 | [单次纯文本调用](references/gemini-polish.md) |

## 交互模式

- **直接润色**：短段落、局部修改或明确要求“直接改稿”时，内部识别问题后
  同轮改写并核对，默认只交干净稿。
- **成稿清理**：整篇“去 AI 味”“检查后润色”默认先交带位置、例句、具体
  改法和保留理由的诊断报告，收到用户接受或调整后再改。已有明确直接改稿
  要求时不增加确认；只问问题的回复不视为接受。
- **只检查**：只交问题和建议，不改正文。用户要求前后对照时另交报告，
  不把报告标记写入干净稿。
- **新写图文**：直接应用共享原则；非虚构长文与大幅扩写先检查材料是否足够。
  成稿诊断的确认流程不阻断正在制作的图表、页面、幻灯片或旁白；只对实质
  缺失的信息或范围变更提问。

先读作者的风格参考，逐处区分拟改、保留、误报和待核。脚本候选由模型复核，
不凭密度、句长或单个词句自动改写。作者习惯优先于通用风格偏好，事实不变。

## 执行与交付

按选定模式定位问题，最小改写，再对照原稿检查信息、结构、受保护内容和
读者可见的全部文字。诊断所用的候选和处置保留工作记录，不写进成品。
不以清空命中、制造参差或判断作者来源为目标。

离线检测与 Markdown 对比命令见中文诊断参考；仅使用 Python 3 标准库。
上游来源、固定版本及不同材料的许可见 [SOURCES.md](SOURCES.md)。
